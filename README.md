# Робот-художник с искусственным интеллектом

Робот на базе координатного плоттера (кинематика H-bot), который распознаёт жесты и голос пользователя, генерирует изображение по наброску и текстовой подсказке (Stable Diffusion + ControlNet) и рисует его маркером на бумаге. Устройство собрано в корпусе чемодана.

Проект выполнен в рамках Всероссийской олимпиады школьников (профиль «Робототехника», технология/труд), ГБНОУ «Президентский ФМЛ №239». Полная пояснительная записка — в [`docs/`](docs).

---

## Идея

Пользователь рисует пальцем в воздухе набросок и произносит тему открытки. Робот:

1. по видео с камеры распознаёт кисть руки и жесты (без каких-либо контроллеров/перчаток — только компьютерное зрение);
2. переводит траекторию пальца в линию на холсте;
3. распознаёт голосовую подсказку и переводит её на английский;
4. генерирует по наброску и тексту 3 варианта изображения нейросетью img2img (Stable Diffusion 1.5 + ControlNet-Scribble);
5. превращает выбранное растровое изображение в непрерывную траекторию заливки контуров, которую физически можно нарисовать одним маркером;
6. рисует получившуюся открытку на листе А5 плоттером, отслеживая, не мешает ли этому процессу рука человека в рабочей зоне.

В проекте задействованы: компьютерное зрение реального времени, классификация жестов собственной нейросетью, генеративная модель (Stable Diffusion), C++-модуль для расчёта траектории закраски растра, интеграция C++/Python через `ctypes`, прошивка ЧПУ (Marlin) и GUI на tkinter.

## Аппаратная часть (кратко, для понимания контекста ПО)

- **Питание**: аккумулятор 6S1P 16000 мАч + понижающие преобразователи напряжения.
- Механика и корпус спроектированы в КОМПАС-3D (`models/`, `plans/`, `Machine.stp`), детали — лазерная резка фанеры + 3D-печать.

## Структура ПО

Весь код, кроме одного модуля траектории, написан на **Python**; вычислительно критичный модуль генерации траектории заливки — на **C++**, скомпилирован в разделяемую библиотеку и вызывается из Python через `ctypes`. Такое разделение осознанное: ИИ-части нужна простота интеграции с экосистемой ML (PyTorch/TensorFlow/Keras), а геометрическому алгоритму — сырая производительность и доступ к параллелизму GPU.

### Модуль жестового управления

| Файл | Назначение |
|---|---|
| `gesture_recognizer.py` | Отдельный процесс: получает кадры с камеры, прогоняет через **MediaPipe HandLandmarker** (21 ключевая точка кисти) и через собственную обученную сеть-классификатор жестов. |
| `mlmodels/static.keras`, `convert_tensorrt.py` | Классификатор жестов: `Conv1D → Conv1D → Dense`, обучен на 20 эпохах на собственном датасете (см. `gen_ds.py`, `dataset/*.npy` — записи координат ключевых точек для жестов `open`/`ok`/`up`/`dislike`, собраны покадровым разбором отснятого видео). Дополнительно оптимизирован через **TensorRT SDK** (`convert_tensorrt.py`, `mlmodels/static_tftrt/`) для ускорения инференса на GPU. |
| `commander.py` | Конечный автомат высокого уровня, интерпретирующий последовательность жестов в действия: `Thumb_Up` — начать/закончить рисование или подтвердить выбор («да» в диалогах), `Thumb_Down` — отклонить вариант («нет»), `Pointing_Up` — переместить курсор, «щипок» большого и указательного пальца (порог по отношению межпальцевого расстояния к длине пальца) — «зажать» и вести линию (жест `Click` определяется отдельно от ML-классификатора чисто геометрически), `Open_Palm` ×2 — очистить холст. |
| `utilites.py` | Общие геометрические функции (расстояние между landmark'ами, отрисовка скелета кисти, линейная интерполяция координат камера → экран). |

Межпроцессное взаимодействие построено на `multiprocessing.Process/Queue/Value`: захват видео, распознавание жестов, генеративная нейросеть и GUI выполняются в **параллельных процессах**, синхронизированных через очереди и разделяемые примитивы, — иначе тяжёлый инференс диффузионной модели «заморозил» бы интерфейс.

Отдельная деталь: координата указательного пальца транслируется не напрямую в canvas, а в системный курсор мыши через `pyautogui` (`Commander.move`), а сама линия на холсте рисуется по отдельным командам (`set_start`/`draw_line`/`end_line`), отправляемым в GUI-процесс через очередь — canvas в `interface.py` намеренно не подписан на нативные события мыши tkinter, вся отрисовка идёт только через этот канал.

### Голосовой ввод

Распознавание речи и перевод реализованы прямо в `Commander.listen()` (`commander.py`): запись с микрофона через `speech_recognition`, распознавание русской речи (Google Speech API), перевод на английский через `googletrans` — для передачи в англоязычную по природе модель Stable Diffusion. Подтверждение распознанной фразы также идёт жестами (`Thumb_Up`/`Thumb_Down`) через тот же `move_while`, то есть голосовой и жестовый каналы переиспользуют одну и ту же логику ожидания. В репозитории также есть `google_speech.py` с похожей автономной функцией `recognize_and_translate` — в текущем пайплайне она не импортируется и не используется, судя по всему это более ранняя версия того же функционала.

### Генеративная нейросеть

`generator.py` — управление диффузионным пайплайном через библиотеку **`diffusers`**:

- **Stable Diffusion 1.5** + **ControlNet-Scribble** (`lllyasviel/sd-controlnet-scribble`) — набросок пользователя используется как структурное условие (contour-conditioning) генерации, а не просто как затравка, что даёт предсказуемую композицию итоговой картинки;
- планировщик **UniPCMultistepScheduler** — ускоренный сэмплер, позволяющий получить качественный результат за меньшее число шагов диффузии;
- **DeepCache** — кэширование промежуточных активаций UNet между шагами денойзинга для ускорения инференса;
- **tomesd** (Token Merging for Stable Diffusion) — слияние похожих токенов внимания, снижение вычислительной нагрузки без заметной потери качества;
- **xFormers** memory-efficient attention + `channels_last` memory format для UNet/VAE — оптимизация под конкретную архитектуру GPU;
- инференс выполняется на CUDA, весь пайплайн запущен в отдельном процессе, прогресс диффузии (шаг за шагом) прокидывается обратно в GUI через очередь для прогресс-бара.

Набор оптимизаций (DeepCache, tomesd, xFormers) выбран, чтобы уложить генерацию в приемлемое время на одной видеокарте с 12 ГБ видеопамяти при демонстрации вживую.

### Определение бумаги в рабочей зоне

`detect_paper.py` — компьютерное зрение поверх OpenCV/scikit-image: HSV-маскирование по цвету реперных зелёных меток на листе, поиск контуров, `minAreaRect` + сопоставление углов, перспективная трансформация (`warpPerspective`) для приведения снятого листа к прямоугольнику, повторное выделение внутренней зелёной рамки на выровненном изображении фильтром Канни для точного определения границ печатной области.

### Перевод изображения в траекторию плоттера

**Постановка задачи**: дано растровое бинарное изображение контуров (после `canny` + бинарная дилатация в `drawer.py`/`utilites.py`), нужно построить один непрерывный путь маркера конечной толщины `d`, который закрасит все контурные пиксели, минимизируя количество отрывов пера и лишних перемещений. По формулировке это близко к задачам покрытия зоны обхода (area coverage / Chinese postman) на нерегулярной области, для которых в общем случае нет простого точного решения за разумное время, поэтому используется эвристика.

**Алгоритм** (`trajectory.cpp`, экспортируется как `extern "C"` для вызова из Python):

1. Случайно выбирается стартовая точка, вокруг которой в радиусе `d/2` нет ни закрашенных, ни выходящих за рисунок точек.
2. Между текущей и следующей точкой строится путь (`get_path`), и вдоль всего пути закрашивается «дорожка» шириной `d` (имитация толщины реального маркера) — заливка выполняется BFS-подобным обходом (`fill_area`) с деками и посещённостью, а не наивным перебором пикселей.
3. Далее ищется следующая точка на расстоянии `d + 1` от текущей, удовлетворяющая тому же условию; если такой нет — берётся случайная валидная точка на изображении; если и такой нет — условие ослабляется (достаточно не выходить за границы исходной маски).
4. Цикл повторяется, пока не останется незакрашенных пикселей.
5. Результат — последовательность координат с маркерами разрывов (`±1e9`), которую `plotter.py` превращает в G-code, сшивая соседние фрагменты и вставляя команды подъёма/опускания пера между несвязными участками.

**Производительность и GPU-параллелизм.** При обработке реалистичных изображений число точек достаточно велико, чтобы наивная реализация на C++ работала медленно. Часть циклов переписана с использованием алгоритмов `std::execution`/`stdpar` (C++17), и модуль компилируется компилятором `nvc++` из NVIDIA HPC SDK с флагами `-stdpar -gpu=managed,cuda...,cc...` — стандартные алгоритмы STL (`transform`, `reduce`, `any_of`) в этом случае выполняются на GPU без написания CUDA-кернелов вручную. По оценке из пояснительной записки, это даёт прирост скорости на порядок по сравнению с однопоточным CPU-вариантом.

**Компиляция на лету.** `drawer.py::TrajectoryLib` сравнивает текущий исходник `trajectory.cpp` с сохранённой предыдущей версией (`lib/trajectory.prev`) и, если код изменился, перекомпилирует `.so`-библиотеку прямо во время работы программы (JIT-подобная схема разработки для C++/GPU кода).

**Мост Python ↔ C++.** Через `ctypes.CDLL` и `numpy.ctypeslib.ndpointer` с явной типизацией указателей (2D/3D массивы `float128`/`int32`) — передача сырых NumPy-буферов в скомпилированную библиотеку без копирования и без обёрточных биндингов вроде pybind11/Cython (в проекте также есть отдельные эксперименты с Cython, см. `tests/test_cython/`).

### Управление плоттером и прошивка

- `plotter.py` — класс `Plotter(serial.Serial)`: отправка G-code по последовательному порту с построчным подтверждением (`ok\n`), автокалибровка угла сервопривода по срабатыванию концевого выключателя, расчёт задержек между командами по фактической скорости подачи, а также **параллельный процесс безопасности** `HandChecker` — во время печати отдельный процесс детектирует руку человека в рабочей зоне через тот же MediaPipe-детектор и ставит печать на паузу, если пользователь потянулся к плоттеру.
- [`Marlin/`](Marlin) — используется прошивка **Marlin** (популярная прошивка для 3D-принтеров), сконфигурированная под кинематику **CoreXY/H-bot** и плату `PROTONEER_CNC_SHIELD_V3`, с урезанной осью Z (заменена на сервопривод пера).

### Интерфейс пользователя

`interface.py` — GUI на `tkinter`: собственные виджеты со скруглёнными углами и кастомной отрисовкой на `Canvas` (`RoundedFrame`/`RoundedButton`, ручное построение сглаженных многоугольников, авто-перенос текста по ширине виджета), полноэкранное окно с превью видео с камеры, индикатором состояния рисования (цветовой светофор), прогресс-баром генерации, попапом выбора толщины линии и блоком пошаговой инструкции по жестам для новых пользователей. Все тяжёлые операции (распознавание, генерация, печать) выполняются в фоновых процессах и общаются с GUI-процессом строго через очереди команд (`commands_queue`), что нужно, поскольку `tkinter` не является потокобезопасным.

### Обучение и вспомогательные ноутбуки

- `model.ipynb` — подготовка датасета жестов и обучение классификатора (`Conv1D`-архитектура на Keras/TensorFlow, `L2`-регуляризация), там же — эксперименты с настройкой пайплайна Stable Diffusion.
- `gen_ds.py` — сбор обучающей выборки: покадровое считывание landmark'ов руки с камеры и сохранение в `.npy`.
- `paper.ipynb`, `convert.ipynb` — вспомогательные эксперименты (отладка детекции бумаги, конвертации моделей).
- `draw_logo.py` — служебный скрипт печати заранее заданных изображений (например, логотипа) в обход основного пайплайна жестового ввода — использовался для тестирования плоттера отдельно от ИИ-части.

## Особенности реализации

- Захват видео, распознавание жестов, генерация изображения и GUI выполняются в отдельных процессах (`multiprocessing`), обмен данными — через очереди и разделяемые значения, а не напрямую.
- В проекте сочетаются разные модели вычислений: CUDA-инференс нейросетей (PyTorch/TensorRT), GPU-параллелизм через `stdpar`/`nvc++` в C++-модуле траектории, обычный CPU-код для CV и GUI.
- Обмен данными между Python и C++ идёт напрямую через `ctypes` и `numpy.ctypeslib.ndpointer`, без промежуточных биндинг-генераторов (pybind11/Cython); типы указателей и layout памяти согласуются вручную.
- Во время печати параллельно работает CV-детектор руки в рабочей зоне (`HandChecker`), который ставит плоттер на паузу при вторжении.
- Заливка контура маркером конечной толщины реализована собственным эвристическим алгоритмом (жадный обход ближайшей допустимой точки с постепенным ослаблением условий при тупике), а не сторонней библиотекой.
- Угол подъёма сервопривода пера определяется автокалибровкой по концевому выключателю при каждом запуске, а не задаётся константой в коде.

## О запуске

Проект **не является «plug-and-play» приложением** и не предназначен для запуска на произвольной машине без соответствующего физического робота. Он поднимался в окружении, куда были заранее установлены и состыкованы по версиям, в частности:

- CUDA Toolkit и драйверы NVIDIA под конкретную видеокарту;
- PyTorch + `diffusers`/`transformers`/`accelerate` (с загрузкой весов Stable Diffusion 1.5 и ControlNet-Scribble из HuggingFace);
- TensorFlow/Keras + TensorRT SDK;
- MediaPipe с моделью `hand_landmarker.task`;
- NVIDIA HPC SDK (компилятор `nvc++`) для сборки C++/GPU-модуля траектории под конкретную вычислительную архитектуру GPU (`cc86`);
- OpenCV, scikit-image, `pyserial`, `SpeechRecognition`, `googletrans`, `pyautogui`, `webcolors` и другие Python-зависимости интерфейса;
- прошитая плата Arduino Mega с Marlin, физически подключённая по serial, и подключённые камеры/микрофон.
